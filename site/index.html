功能

你需要的，都在一个面板里

不打扰你工作，也不让你在插件页里来回翻找。需要你决定时，它才出现。

插件与内核检查

插件读 profile 与 bundle 列表；内核显示随 DSH NEXT 内置的版本。DSH NEXT 自身负责应用更新。

数据目录随你放

把 DSH NEXT 指向你选择的文件夹；可以只切换指针，也可以复制插件、工作区、对话和存储后再切换。

按版本忽略

插件可以只忽略“这一次”的版本；上游发新版本会重新提示，已忽略项可随时取消。

实时进度

进度条、当前阶段和 pnpm 输出末行。即使内核不转发事件，阶段计时也会兜底推进。

一键全部更新

按顺序更新所有待更新插件，逐行显示进度；某个失败时保留错误，其余继续。

完成即消失

更新成功的插件立即从列表移除，不再闪回“更新”按钮，也不会催你重复检查。

需要时重启

替换插件后 DSH NEXT 需要重启才能加载新代码；面板会提示，重启由标题栏完成。

可拖动，可换肤

拖标题栏移动、双击复位、记住位置、Esc 关闭；点右上角三个点还能调宽度、强调色、背景和不透明度，设置会记住。

怎么工作

打开 DSH，剩下的交给它

检查是普通 HTTPS 请求；更新调用 DSH 自己的插件管理器。没有隐藏的模型调用。

  1. 01
    启动时静默检查

    读取你的 profile 与已安装版本，对比 npm registry，并读 DSH NEXT 的当前版本与数据目录。

  2. 02
    有更新才提醒

    侧边栏出现数量徽标；点开面板，看到每一层的当前版本与最新版本。

  3. 03
    更新，必要时重启

    单个或全部更新；失败自动恢复旧版本。需要重启时一键完成。

profile 配置示例
# cordis.patch.yml
- id: plugin-updater
  name: dsh-plugin-updater
  config:
    autoCheck: true
    checkEngine: true
    registry: https://registry.npmjs.org

改完重启 DSH NEXT 生效。完整配置见 README。

安装

一分钟接入你的 DSH

推荐从 GitHub 安装；想固定版本就用 tag。安装后重启 DSH NEXT。

推荐

从 GitHub 安装

在 DSH 的 设置 → 插件 → 添加插件 里填：

github:TT10-24/dsh-plugin-updater

或者用终端

dsh plugin --profile desktop add github:TT10-24/dsh-plugin-updater
固定版本

锁在某个 Release

适合想稳定复现的环境。把版本号换成你需要的 tag：

dsh plugin --profile desktop add github:TT10-24/dsh-plugin-updater#v0.3.6

安装 / 更新后重启 DSH NEXT。插件会出现在侧边栏底部，显示「查看更新」。

常见问题

你可能想先知道

会消耗 token 吗？

不会。检查只是普通 HTTPS 请求；更新调用 DSH 插件管理器与 pnpm。没有 LLM、没有 agent、没有 subagent。

为什么更新后要重启？

替换已安装插件的代码后，运行中的 DSH NEXT 仍持有旧模块；新增组件行也要重启才会进入运行树。面板会提示，重启由标题栏完成。

更新失败会怎样？

插件会尝试恢复旧版本，并把原因显示在对应插件行下方。DSH NEXT 里遇到无法热卸载的宿主插件时，会自动改为覆盖安装并提示重启；失败仍会回滚，也可以到插件页手动批准构建脚本。

迁移数据目录会复制什么？

会复制 profiles（插件配置与插件包）、sessions（对话）、storages（存储）和根目录的凭据/偏好文件；logs 与缓存不复制。源目录不会被删除。

怎么把数据迁移到另一个盘？

面板的 DSH NEXT 区域点「迁移数据目录」，选择目标文件夹。数据已在目标盘时只切换指针；目标为空时勾选「同时复制现有数据」，复制完成后再写指针。源目录不会被删除。

怎么固定版本或回滚？

安装时用 #v0.3.6 固定 tag；回滚就重新安装旧 tag，然后重启 DSH NEXT。
